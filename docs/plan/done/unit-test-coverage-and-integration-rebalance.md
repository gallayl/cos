## Summary
First ready slice for R25 #11: add deterministic host unit-test coverage in quick-win areas using existing Unity/mock patterns, with minimal behavior-preserving extraction/seams only where needed inside those areas, and perform bounded integration-test rebalancing only for explicitly agreed duplicated logic-contract assertions (with per-case rationale and preserved platform/runtime confidence). Broader `http_api.c` handler-glue extraction and `network_http.c` state-machine decomposition are deferred to follow-up ready items.

## Scope
- **Host unit-test additions/expansions (in scope):**
  - **Shell FS command semantics:** add/strengthen host tests for `ls`, `cat`, `touch`, `mkdir`, `cd`, `pwd`, `rm`, `rmdir`, `cp`, `mv`, `hexdump`, `info` (and directly related deterministic command behavior/messages/error paths) via command handlers/logic with `mock_filesystem` (and existing shell mocks as needed), covering success/error cases such as nonexistent targets, dir-not-empty, overwrite/copy rules, and path resolution interactions consistent with existing VFS/path behavior.
  - **HTTP multipart/static/path helper edge cases:** add/strengthen host tests for pure/helper behavior and edge cases in/derived from `components/http_server/src/http_multipart.c`, `components/http_server/src/http_static.c`, and `components/http_server/src/http_path.c` (boundary/header parsing, chunk/state transitions where host-testable, path resolution/safety rules, content-type/static lookup decisions) using existing patterns/mocks (e.g. `mock_httpd`) where feasible.
  - **`network_url` edge expansion:** extend `test/test_network_url.c` with additional URL parsing/normalization/resolution, base/get-base contracts, and header/method/timeout validator edge cases as feasible within existing seams.
  - **`time_sync` edge expansion:** extend `test/test_time_sync.c` for deterministic invalid-config/state-transition/formatting/command-output/callback-driven edge behavior using existing mocks (`mock_sntp`/timer/system mocks) as feasible; real SNTP/network timing remains out of scope.
- **Bounded refactors/seams (allowed, constrained):** minimal, behavior-preserving helper extraction or test seams are allowed **only inside the in-scope areas above** and only when they directly enable host tests (e.g. extract pure parsing/validation/mapping helpers from multipart/static/path or small shell/time_sync helpers; make internal logic callable in unit tests). No new heavy dependencies. Console input transport/read seam is already landed (R25 #4 progress) and may be used but not expanded except if strictly required by in-scope tests.
- **Integration rebalancing (bounded, in scope):** where equivalent host coverage is added and platform confidence is preserved, may remove or simplify **deterministic FS command logic/message/error assertions** in `integration_test/test_shell_fs` that are duplicated by the new/strengthened host `mock_filesystem` tests. No rebalancing edits required for `test_vfs_ops`, `test_nvs_calibration`, `test_system`, `test_init_sequence`, `test_esp_littlefs`, or `test_stability` in this slice unless a specific assertion is proven redundant (only then, with recorded rationale). 
- **Per-case rationale (required for every integration edit):** record in the implementation PR/plan progress: case/assertion removed or simplified, covering host test(s), and why platform/runtime confidence is unchanged.

- **Mock fidelity:** `mock_filesystem`/other mocks may not match LittleFS/NVS/ESP-IDF/RTOS semantics; do not remove platform-boundary integration coverage.
- **Integration confidence:** even "duplicated" REPL assertions can catch wiring issues; apply bounded rebalancing only with per-case rationale and preserved platform confidence.
- **Scope creep:** `http_api.c` glue and `network_http.c` stateful client are explicitly out of scope for this slice; escalate to follow-up items if needed.
